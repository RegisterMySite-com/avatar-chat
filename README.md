# Avatar Chat

Real-time multi-user chat built on **Cloudflare Workers**, **Durable Objects**, and **PartyServer**, with:

- Circular **image avatars** (DiceBear placeholders you can replace with your own logos)
- Public room, private invite rooms, and a direct “Message Admin” room
- Live presence
- Browser notifications + soft chime
- Light / dark theme
- Full **admin moderation dashboard** (view rooms, participants, delete messages/rooms)

Live pattern is based on Cloudflare’s [durable-chat-template](https://github.com/cloudflare/templates/tree/main/durable-chat-template), extended with image avatars and an admin API.

## Deploy with one click

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/RegisterMySite-com/avatar-chat)

After the button finishes:

1. In the Cloudflare dashboard go to **Workers & Pages** → your new Worker.
2. Open **Settings** → **Variables** and add a secret:
   - Name: `ADMIN_SECRET`
   - Value: a strong password of your choice (used for the `/dashboard` login)
3. Redeploy if prompted so the secret is available.

The admin dashboard is at `https://<your-worker>.workers.dev/dashboard`.

## Deploy from the CLI (detailed)

### Prerequisites

- A [Cloudflare account](https://dash.cloudflare.com/sign-up)
- [Node.js](https://nodejs.org/) 18+ (20+ recommended)
- [Git](https://git-scm.com/)
- A terminal (macOS / Linux / WSL / Windows Terminal)

### 1. Clone this repository

```bash
git clone https://github.com/RegisterMySite-com/avatar-chat.git
cd avatar-chat
```

### 2. Install dependencies

```bash
npm install
```

This installs React, PartyServer / PartySocket, nanoid, esbuild, TypeScript, and Wrangler.

### 3. Generate Worker types (optional but recommended)

```bash
npm run cf-typegen
```

This writes `src/server/worker-configuration.d.ts` so TypeScript knows about your Durable Object and asset bindings.

### 4. Local development

```bash
npm run dev
```

Wrangler starts a local server (usually `http://127.0.0.1:8787`). Open it in a browser, pick a name + avatar, and open the same URL in another tab or device to chat.

Hot tips while developing:

- The client is rebuilt by the `build.command` in `wrangler.json` on each deploy / dev start.
- Change avatars in `src/shared.ts` (`AVATARS` array). Use any square image URL or path under `public/`.
- Default admin password locally is `admin` unless you set `ADMIN_SECRET`.

### 5. Set the admin secret for production

Create a file `.dev.vars` for local overrides (never commit it):

```bash
echo 'ADMIN_SECRET=your-strong-password-here' > .dev.vars
```

For production, set the secret on the Worker (do this **before** or right after the first deploy):

```bash
npx wrangler secret put ADMIN_SECRET
# paste your password when prompted
```

Or in the dashboard: **Workers & Pages** → your Worker → **Settings** → **Variables** → **Add** → type **Secret**.

### 6. Deploy

```bash
npx wrangler deploy
```

Or use the npm script:

```bash
npm run deploy
```

First deploy will:

1. Run the esbuild step (`src/client/index.tsx` → `public/dist/`)
2. Upload static assets from `public/`
3. Create the Worker and the Durable Object classes `Chat` and `RoomRegistry` (see migrations in `wrangler.json`)

When it finishes you get a URL like:

```
https://avatar-chat.<your-subdomain>.workers.dev
```

### 7. Verify

1. Open the public URL → choose a display name and a circular avatar → join **Public Room**.
2. Open the same room in another browser / incognito window and send messages.
3. Visit `/dashboard`, sign in with the `ADMIN_SECRET` you set, and confirm you can see rooms and delete messages.

### 8. Custom domain (optional)

In the Cloudflare dashboard:

**Workers & Pages** → your Worker → **Settings** → **Domains & Routes** → **Add** → attach a custom domain or route.

### Key Durable Objects

| Class           | Purpose                                      |
|-----------------|----------------------------------------------|
| `Chat`          | One instance per chat room (messages + presence via WebSockets) |
| `RoomRegistry`  | Global list of rooms for the admin dashboard |

### Admin API (requires `Authorization: Bearer <ADMIN_SECRET>`)

| Method | Path | Description |
|--------|------|-------------|
| POST   | `/api/admin/login` | Validate password, returns token |
| GET    | `/api/admin/rooms` | List rooms + live participant counts |
| GET    | `/api/admin/rooms/:id/messages` | Messages in a room |
| DELETE | `/api/admin/rooms/:id/messages/:msgId` | Delete one message |
| DELETE | `/api/admin/rooms/:id` | Clear room + unregister |

## Replacing the placeholder avatars

Edit `src/shared.ts`:

```ts
export const AVATARS = [
  "/avatars/logo-01.png",
  "/avatars/logo-02.png",
  // or full CDN URLs
];
```

Put image files in `public/avatars/` (create the folder). Prefer square images; CSS crops them to circles with `border-radius: 50%` and `object-fit: cover`.

After changing client code, redeploy (`npx wrangler deploy`) so esbuild rebuilds `public/dist/`.

## Troubleshooting

### “New version of script does not export class 'ChatRoom'…”

An older deployment used a different Durable Object class name. This repo exports **`Chat`** and **`RoomRegistry`**.

- Prefer deploying under a **new Worker name** (or delete the old Worker) so migrations start clean.
- If you must keep the same name and the old class is no longer needed, add a migration in `wrangler.json`:

```json
"migrations": [
  {
    "tag": "v1",
    "new_sqlite_classes": ["Chat", "RoomRegistry"]
  },
  {
    "tag": "v2",
    "deleted_classes": ["ChatRoom"]
  }
]
```

Then deploy again. Only delete classes when you are sure no important data remains in those objects.

### Admin login fails

Confirm `ADMIN_SECRET` is set on the **same** Worker you are hitting, and that you redeployed (or used `wrangler secret put`) after adding it.

### Avatars show as broken images

- DiceBear URLs need network access from the browser (they are external SVGs).
- For offline / custom logos, switch `AVATARS` to paths under `public/` and redeploy.

### Client changes not visible

The browser may cache `public/dist/index.js`. Hard-refresh (Ctrl/Cmd+Shift+R) or open a private window after deploy.
